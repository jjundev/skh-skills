# 확인 질문 분류 (C1–C6)

실제 시험 화면에서 관찰한 6문항을 기준으로 만든 분류다. 시험 LLM은 한 문항에 3–4개 하위 질문을 묶고, 제출물의 구체적 이름이나 문서 문장을 인용한다. 예상 질문도 같은 모양으로 만든다.

## C1. 설계 결정과 트레이드오프
- 관찰 예: "노선 계산에서 전역 최적해를 구하거나 최적화 라이브러리를 쓰지 않고, 기준선을 먼저 만든 뒤 시간·후보 수에 제한을 둔 지역 탐색으로 개선하는 구조를 택했습니다. 이 방식을 택한 이유, 고려했던 대안과의 차이, 그리고 이 선택으로 포기한 것은 무엇인가요?"
- 질문 모양: <제출물의 결정을 구체적으로 서술> + 택한 이유 + 대안과의 차이 + 포기한 것.
- 재료: 핵심 알고리즘·저장소·동기/비동기 선택, 문서에 "대신 ~를 택했다"로 적힌 곳.
- 강한 답: 제약(시간·환경·요구사항) → 선택 → 대안 1개와 차이 → 포기한 것을 숫자나 구체 사례로.

## C2. 요청 흐름과 상태 소유권
- 관찰 예: "HR 운영자가 '노선 생성'을 눌렀을 때부터 구성원이 자기 노선을 조회할 수 있게 되기까지, 요청이 어떤 구성요소들을 거치고 상태(작업·계획·활성 데이터셋)는 어디에 저장되고 누가 소유하는지 흐름을 설명해 주세요."
- 질문 모양: <사용자 행동 A>부터 <결과 B>까지 + 거치는 구성요소 + 상태별 저장 위치 + 소유자.
- 재료: 진입점 → 핸들러 → 서비스 → 저장소 호출 경로, 전역 변수·DB·캐시.
- 강한 답: 단계별 함수 이름, 상태마다 "어디에, 누가 쓰고, 누가 읽는지", 문서와 코드가 다르면 코드 기준 + 차이 인정.

## C3. 구현·검증한 것 vs 가정으로 남긴 것, 검증 경로
- 관찰 예: "이 서비스에서 실제로 구현해 검증한 부분과 구현하지 않았거나 가정으로 남긴 부분을 구분해 설명해 주세요. 그리고 다른 평가자가 '생성된 계획이 운영 규칙을 지킨다'는 주장을 확인하려면 어떤 경로(테스트·명령·파일)를 보면 되나요?"
- 질문 모양: 구현+검증 / 미구현·가정 구분 + <문서의 특정 주장>을 제3자가 확인할 경로.
- 재료: 주장 원장의 ✅/🟡/❌.
- 강한 답: 세 묶음으로 나눠 말하고, 경로는 테스트 이름 + 실행 명령 + 파일. 🟡는 "코드는 있으나 테스트 없음"이라고 정확히.

## C4. 실패 모드
- 관찰 예: "계획 생성 도중 최적화가 시간 제한에 걸리거나, 워커 프로세스가 죽거나, 생성 중에 운영자가 데이터셋을 바꿔 적용하면 각각 시스템은 어떻게 동작하고 기존 계획과 구성원 화면은 어떤 상태가 되나요?"
- 질문 모양: 실패 상황 2–3개 나열 + 각각 시스템 동작 + 기존 데이터·사용자 화면 상태.
- 재료: 타임아웃·예외 처리, 프로세스 재시작 시 상태 유실, 동시 변경, 문서의 신뢰성 주장.
- 강한 답: 상황마다 "상태 값 → 사용자에게 보이는 것", 처리 안 된 상황은 미구현이라고 먼저 말함.

## C5. 규모와 극단 입력
- 관찰 예: "구성원 수·기간이 크게 늘어나거나(예: 2000명, 30일) 차량 정원이 1석처럼 극단적으로 작아지면 어떤 부분이 병목이나 위험이 되나요? 이를 어떻게 확인했고, 결과를 신뢰하기 위해 앞으로 추가로 해볼 검증이나 개선은 무엇인가요?"
- 질문 모양: <큰 숫자 예시> 또는 <극단값> + 병목·위험 + 어떻게 확인했나 + 앞으로 할 검증.
- 재료: 중첩 루프, 고정 상한 상수, 전체 복사, 메모리 자료구조, 검증 없는 입력.
- 강한 답: 병목을 코드 위치로 지목, 확인 방법은 [제출물] 근거가 없으면 "제출 시점에는 측정하지 않았다"고 말하고 할 실험을 제시.

## C6. AI 협업 과정
- 관찰 예: "AI_COLLABORATION.md에 적은 '소수 단위 이동시간을 분 단위 시간표로 변환할 때 생기는 계산 기준 문제' 처리 과정을 실제로 어떻게 진행하셨나요? 이 문제를 처음 어떻게 알게 되었고, AI가 제안한 해결 방식 중 받아들인 것·고치거나 버린 것은 무엇이며, 각각 어떤 근거(실행한 테스트나 확인 결과 등)로 판단하셨는지 구체적으로 설명해 주세요."
- 질문 모양: <협업 문서 항목 제목 그대로 인용> + 처음 알게 된 계기 + 받아들인 것 / 버린 것 + 각각의 근거.
- 재료: AI 협업 문서의 각 항목(항목마다 질문 1개 우선), 커밋 메시지, `--transcripts`.
- 강한 답: 문서에 있는 사실만 1인칭 과거형. 계기·당시 생각처럼 문서에 없는 부분은 `[본인 기억으로 채우기]` 칸.
